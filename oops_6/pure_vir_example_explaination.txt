# Introduction

Ye example ek saath C++ ke 4 important OOP concepts explain karta hai:

1. Pure Virtual Function
2. Abstract Class
3. Runtime Polymorphism
4. Virtual Destructor

Example:

```cpp
class PaymentMethod {
public:
    virtual void processPayment(double amount) = 0;

    virtual ~PaymentMethod() {}
};
```

# Pure Virtual Function Ka Role

Base class:

```cpp
class PaymentMethod {
public:
    virtual void processPayment(double amount) = 0;
};
```

Yaha:

```cpp
= 0
```

ka matlab hai:

> "Main sirf contract define kar raha hoon. Implementation mujhe nahi pata."

Har derived class ko implementation deni hi padegi.

---

# Abstract Class

Jis class me kam se kam ek pure virtual function ho:

```cpp
virtual void processPayment() = 0;
```

Wo class **Abstract Class** ban jaati hai.

Example:

```cpp
PaymentMethod p;
```

❌ Error

Abstract class ka object create nahi kar sakte.

---

# Agar Override Na Kare To?

```cpp
class UPI : public PaymentMethod
{
};
```

UPI ne `processPayment()` implement nahi kiya.

To `UPI` bhi abstract class ban jayegi.

```cpp
UPI obj;
```

❌ Error

Object create nahi kar sakte.

---

# Base Class Implementation Kyu Nahi Deti?

Payment process karne ka logic har method ka alag hota hai:

* Credit Card
* UPI
* Net Banking

Sabka algorithm different hai.

Isliye base class sirf contract define karti hai:

```cpp
processPayment()
```

Implementation derived classes deti hain.

# Destructor Kya Hota Hai?

Constructor object create hone par chalta hai.

Destructor object destroy hone par chalta hai.

Example:

```cpp
class Test {
public:
    Test() {
        cout << "Constructor\n";
    }

    ~Test() {
        cout << "Destructor\n";
    }
};
```

### Output

```text
Constructor
Destructor
```

# Problem Without Virtual Destructor

Suppose:

```cpp
class PaymentMethod {
public:
    ~PaymentMethod() {
        cout << "PaymentMethod Destructor\n";
    }
};
```

Aur:

```cpp
class CreditCard : public PaymentMethod {
public:
    ~CreditCard() {
        cout << "CreditCard Destructor\n";
    }
};
```

Main:

```cpp
PaymentMethod* p = new CreditCard();

delete p;
```

### Output

```text
PaymentMethod Destructor
```

Sirf base destructor chala.

Derived destructor nahi chala.

---

# Ye Dangerous Kyu Hai?

Suppose:

```cpp
class CreditCard : public PaymentMethod {

    int* data;

public:

    CreditCard() {
        data = new int[100];
    }

    ~CreditCard() {
        delete[] data;
    }
};
```

Agar:

```cpp
delete p;
```

Aur destructor virtual nahi hai,

To:

```cpp
delete[] data;
```

kabhi execute nahi hoga.

Result:

❌ Memory Leak

---

# Virtual Destructor Solution

```cpp
class PaymentMethod {
public:
    virtual ~PaymentMethod() {
        cout << "PaymentMethod Destructor\n";
    }
};
```

Ab:

```cpp
PaymentMethod* p = new CreditCard();

delete p;
```

### Output

```text
CreditCard Destructor
PaymentMethod Destructor
```

### Execution Flow

```text
delete p
    |
    v
CreditCard Destructor
    |
    v
PaymentMethod Destructor
```

---

# Hamare Example Mein

```cpp
virtual ~PaymentMethod() {}
```

Meaning:

> Agar base class pointer se derived object delete kiya jaye, to actual derived class destructor pehle call hona chahiye.

# Interview Definitions

## Pure Virtual Function

A function declared with `= 0` that forces derived classes to implement it.

```cpp
virtual void processPayment() = 0;
```

---

## Abstract Class

A class containing at least one pure virtual function.

Objects cannot be created directly.

---

## Runtime Polymorphism

Base class pointer calling derived class function at runtime through virtual functions.

---

## Virtual Destructor

Ensures that when a base class pointer deletes a derived object, the derived destructor executes first.

---

# Golden Rule

Whenever a class contains:

```cpp
virtual function
```

or

```cpp
pure virtual function
```

always prefer:

```cpp
virtual ~ClassName() {}
```

This is standard industry practice.
